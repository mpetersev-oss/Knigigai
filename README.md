# Книгигай

Сайт персональных книг-подарков: пользователь создаёт двух героев (себя и получателя),
выбирает повод и обложку — книга сохраняется по секретной ссылке, регистрация не нужна.

**Этап 1 (готов):** главная, конструктор героев, повод, выбор и настройка обложки, страница книги, админка с синхронизацией картинок.
**Дальше:** страницы книги (мастер вопросов), макет для типографии (блок 215×140 мм, переплёт 220×145 мм), корзина и ЮKassa.

## Как устроено

```
app/            PHP-код (вне публичной папки)
  config.example.php  → скопировать в config.php
  Catalog.php   каталог вещей/поз/обложек (data/source.json + синхронизированные картинки)
  Books.php     книги-черновики, проверка данных
  Admin.php     вход в админку, синхронизация картинок
  Airtable.php  чтение таблицы Poses
data/source.json  описание всех вещей, поз и обложек (выгрузка из старого Webflow CMS)
public_html/    корень сайта
  index.php     API + отдача страницы
  assets/       CSS и JS (без сборки, обычные ES-модули)
  media/        картинки после синхронизации (WebP), в git не хранятся
storage/        кеш каталога (создаётся автоматически)
```

- Стек: PHP 8.1+ и MySQL — то, что есть на тарифе Beget «Оптимум». Никаких Node.js и сборщиков.
- Все картинки персонажей нарисованы в одном кадре 2855×3305. При синхронизации каждая
  обрезается до содержимого и сжимается в WebP (в 15–20 раз легче исходных SVG), а её
  координаты в кадре сохраняются — поэтому слои всегда совпадают.
- Пока картинки не синхронизированы, сайт берёт исходники со старого Webflow CDN
  (работает, но медленно). Позы на обложках появляются после шага 3 синхронизации,
  до этого герои стоят на обложках в базовой позе.

## Установка на Beget

1. **Сайт и база.** В панели Beget: «Сайты» → создать сайт (пока без домена — будет технический адрес
   вида `логин.beget.tech`). «MySQL» → создать базу, запомнить имя, пользователя и пароль.
2. **PHP.** В настройках сайта выбрать PHP 8.1 или новее.
3. **Файлы.** Залить содержимое репозитория в папку сайта так, чтобы `public_html` из репозитория
   совпала с `public_html` сайта, а `app`, `data`, `storage` лежали рядом с ней (уровнем выше).
   Удобнее всего через SSH:
   ```
   cd ~/ИМЯ_САЙТА
   git clone https://github.com/mpetersev-oss/Knigigai.git tmp && cp -r tmp/. . && rm -rf tmp
   ```
   Обновления потом — `git pull` в этой папке.
4. **Настройки.** `cp app/config.example.php app/config.php` и заполнить:
   - `db` — данные базы из шага 1 (таблицы создадутся сами при первом заходе);
   - `admin_password_hash` — хеш пароля админки:
     `php -r "echo password_hash('ВАШ_ПАРОЛЬ', PASSWORD_DEFAULT), PHP_EOL;"`
   - `airtable_token` — токен Airtable с правом `data.records:read` на базу «Lovebooks (Update)»
     (создаётся на https://airtable.com/create/tokens).
5. **Права.** Папки `storage` и `public_html/media` должны быть доступны на запись (обычно уже так).
6. **Картинки.** Открыть `https://ВАШ_АДРЕС/admin` **в Chrome**, войти и нажать по очереди:
   1. «Редактор персонажей» (~260 файлов, несколько минут);
   2. «Обложки» (~45 файлов);
   3. «Позы из Airtable» — по умолчанию подставлены позы, которые используются на обложках.
   Не закрывайте вкладку, пока идёт процесс. Повторный запуск докачивает только недостающее.

## Локальный запуск

```
KG_DB_DSN="sqlite:$PWD/storage/dev.sqlite" \
KG_ADMIN_HASH=$(php -r "echo password_hash('test', PASSWORD_DEFAULT);") \
php -S localhost:8080 -t public_html dev/router.php
```

## Что исправлено по сравнению со старым сайтом

- Нет обязательной регистрации: раньше без входа кнопка «Продолжить» молча не работала.
- Состояние хранится на сервере, а не в sessionStorage — закрытая вкладка ничего не теряет.
- Ошибка сохранения больше не выдаётся за успех; все сообщения на русском.
- Пол по умолчанию одинаковый везде; куртки не пропадают после перезагрузки.
- Позиции вещей не зашиты в код — они берутся из самих картинок при синхронизации.
- Нет скриншота html2canvas: персонаж собирается из лёгких WebP-слоёв.
- Нет внешнего сервера на Netlify и зависимости от лимита вложений Airtable.
- Окно «Автор» больше не спрашивает «Кто получит твою книгу?».
